## 1. 定位与建图（SLAM / AMCL）

### Q：SLAM 和 AMCL 什么关系？为什么必须「先建图再定位」？

**一句话**：SLAM 解决「地图未知 + 我在哪」两个未知数，AMCL 只解决「**地图已知**，我在哪」。所以顺序不可颠倒。

**为什么**：AMCL 是粒子滤波 —— 它把每个粒子「搬到地图上」，用**激光测距与已知地图的匹配度**给粒子打分。地图未知时没有参照物，粒子权重全是噪声，滤波发散。

**实测/出处**：`E-13`、`E-5`。项目里 `slam_toolbox` 建图 → `map_server` 存图 → `amcl` 定位，两条链是两个 launch。

### Q：`slam_toolbox` 参数要调很多吗？

**一句话**：这个项目**一个都不用改**。

**为什么**：`mapper_params_online_async.yaml` 的默认值（`odom` / `map` / `base_footprint` / `/scan` / 分辨率 0.05 / `mode: mapping`）与本项目**完全吻合**。

**实测/出处**：直接 `ros2 launch slam_toolbox online_async_launch.py` 即可建图。见记忆与 `E-13`。

### Q：里程计为什么会漂？`open_loop` 是什么？

**一句话**：`open_loop: true` 表示**里程计不读轮子编码器，直接按「我发的速度指令」积分**。一旦轮子打滑，指令说「走了 1 m」而实际只走了 0.3 m，误差就永久累积。

**为什么**：真里程计应读编码器（`open_loop: false`）。但教材为了仿真稳定设成 `true`。

**实测/出处**：`E-5`。巡逻一圈漂移 **7 m / 38°**，靠 AMCL 纠正。

### Q：那把 `open_loop` 改成 `false` 能不能治好漂移？ 🔥

**一句话**：**不能，反而更差。** 这是个反直觉的实测结论。

**为什么**：漂移的**根因不是积分方式，是轮子真的在打滑**。改成 `false` 后编码器忠实上报「打滑后的真实转速」—— 打滑量照样进 odom，**甚至因为不再被指令速度「理想化」而更接近打滑后的错误轨迹**。

**实测/出处**：`E-13`、`E-5`。同一路线 A/B：

| | `open_loop=true` | `open_loop=false` |
| --- | --- | --- |
| odom 误差 | 16.5 m | **19.97 m** |
| SLAM 误差 | 11 m | **18.68 m** |
| 地图高度 | 20.6 m | **21.2 m** |

**面试话术**：「我一开始也以为是 `open_loop`，做完 A/B 才发现**两种设置都治不了打滑**，所以真因在别处。」

### Q：「SLAM 发散」怎么定位？为什么不该先怪算法？ 🔥

**一句话**：先查**机器人是不是根本没动**。我最后定位到：`机器人物理卡死 → 轮子打滑 → odom 漂 → SLAM 运动先验坏掉 → 扫描匹配失败 → 发散`。**发散是「果」，卡死是「因」。**

**为什么**：SLAM 的输出 = 运动先验（odom）× 观测修正（激光匹配）。运动先验坏掉后，扫描匹配的搜索初值离真值太远，匹配到错误位置，随后越错越远。

**实测/出处**：`E-13`。判据三条同时成立：

1. **Gazebo 真值列冻结**（`gz model -m mybot -p` 连续多秒不变）
2. odom 误差**单调涨**
3. SLAM 误差**跟着 odom 涨**（注意：SLAM 是跟着涨的，不是自己先涨 —— 这点很关键）

### Q：发散的地图长什么样？用什么指标量？ 🔥

**一句话**：地图会**膨胀**。最灵敏的指标是「**障碍格的世界包围盒**」。

**为什么**：位姿漂 → 同一面墙被贴到多个位置 → 地图上出现「幽灵障碍」，包围盒被撑大。

**实测/出处**：`E-13`。

| | 障碍格世界包围盒 | 与项目地图一致率 |
| --- | --- | --- |
| 正常 | **18.7 × 11.0 m** | **96.9 %** |
| 发散 | 19.9 × 17.2 m | 92.8 % |

（房间真值 18.8×11.1 m。）幽灵障碍的**签名**：比对时「只有我有障碍」和「只有你有障碍」两侧数量**相当**（2762 vs 2660）—— 说明是随机错位，不是漏建。

### Q：怎么证明「是卡死导致的」？事后能不能反证？ 🔥

**一句话**：能。我给驾驶脚本加上**避障**后重跑：odom 照样漂到 2.49 m，但 **SLAM 误差全程 0.04~0.09 m，从没发散**。

**为什么**：避障后机器人不再卡死 → 轮子不打滑 → 运动先验干净 → 扫描匹配正常工作。**唯一变量是「卡死」，因果链闭环**。

**实测/出处**：`E-13`。地图包围盒回到 **18.7 × 11.0 m**。

### Q：那怎么知道「扫描匹配确实在干活」？ 🔥

**一句话**：正常行驶时 **SLAM 误差（0.03~0.07 m）比 odom 误差（可到 1.05 m）还小**。

**为什么**：如果 SLAM 只是照抄 odom，两者误差应该一样。SLAM 明显更准 ⇒ 激光匹配在**修正** odom 漂移。这是「融合在工作」的直接证据。

**实测/出处**：`E-13`。

### Q：建图时航点都是「净空合规」的，为什么还是撞？ 🔥

**一句话**：**航点净空 ≠ 路径净空**。

**为什么**：我的测试脚本 `goto()` 是纯贪心（朝目标直发速度、无避障）。两个航点各自离障碍 0.80 m / 0.45 m 看着都安全，但**中间隔着一道家具** → 机器人笔直撞上去卡死。

**实测/出处**：`E-13`。结论：**建图必须保证路径畅通**（用 Nav2 自主导航，或有避障的遥控），不能只挑「点」安全。

## 2. 代价地图（costmap）

### Q：代价地图 0~255 分别是什么？ 🔥

**一句话**：内部有 5 个具名常量（`cost_values.hpp`）：

| 值 | 名字 | 含义 |
| --- | --- | --- |
| 0 | `FREE_SPACE` | 自由 |
| 252 | `MAX_NON_OBSTACLE` | 软代价上限 |
| 253 | `INSCRIBED_INFLATED_OBSTACLE` | **内切**膨胀障碍（硬阻断） |
| 254 | `LETHAL_OBSTACLE` | 致命（真障碍） |
| 255 | `NO_INFORMATION` | 未知 |

**实测/出处**：`E-14`。

### Q：从哪个话题读的才是真实代价？ 🔥

**一句话**：`<ns>/costmap_raw`（`nav2_msgs/Costmap`，0~255）。**别读 `<ns>/costmap`** —— 那是 `nav_msgs/OccupancyGrid`，**代价被压缩到 0~100**。

**为什么**：ROS 1 时代的 `OccupancyGrid` 约定用 −1/0~100，Nav2 为了兼容同时发布一份压缩版。254→100、253→99，**连「有没有障碍」都会判错**。

**实测/出处**：`F-16`。两组数字格数一一对应（3477↔3470、13887↔13885）。
**踩坑记录**：我当时先猜 `int8` 符号回绕（错，负值格数 = 0），又猜 `0/100/−1` 约定（也错）。**正确第一步是 5 秒钟的 `ros2 topic list | grep costmap`。**

### Q：膨胀层的代价公式是什么？ 🔥🔥

**一句话**：是**四段**，不是三段 —— 最容易漏的是**出了 `inflation_radius` 代价直接归零**：

```
d = 到最近致命格的欧氏距离（单位：格）

d == 0                          → 254（致命）
d · res ≤ inscribed_radius      → 253（内切，硬阻断）
d · res >  inflation_radius     → 0    ← 最容易漏的一段
否则                            → 252 · exp( −csf · (d·res − inscribed_radius) )
```

**为什么**：指数衰减 —— 离障碍越远代价越低；**内切半径以内是「悬崖」**（253 挡死）；
而膨胀层**只作用到 `inflation_radius` 为止**（源码里
`if (distance > cell_inflation_radius_) continue;`），再远就不写代价了。

**实测/出处**：`E-15` + `E-22`。拿静态地图的净空按上面四段预测、
和实时 `/global_costmap/costmap_raw` **逐格比 3300 点，不一致率 0.1%**
（`tools/probe_map_vs_costmap.py`）。

> ⚠️ **我在这里栽过一次**：第一版对比脚本漏了第 3 段，得出 **52.8% 的「不一致」**，
> 看起来「证据确凿」，其实全是假的（`F-22`）。
> **学到的是：「大面积不一致」先怀疑自己的模型，而不是数据。**

### Q：「能不能过门」由哪个参数决定？和 `inflation_radius` 什么关系？ 🔥

**一句话**：由**内切半径（`robot_radius`）硬阻断**决定，**不是** `inflation_radius`。

- `inscribed_radius` → 决定「**能不能过**」（硬 253，过不去就是过不去）
- `inflation_radius` / `cost_scaling_factor` → 只管**软代价**，影响「**愿不愿意贴边走**」

**实测/出处**：`E-15`。所以**通道净宽要求 = `2 × 生效内切半径`**。

### Q：配置的 `robot_radius` 为什么不等于生效值？ 🔥

**一句话**：配置 0.22 m，**实测生效 ≈ 0.225 m**（逐桶反推 0.2249 / 扫相符率峰值 0.2255），
差 **~5 mm**，**原因未定位**。

**为什么（诚实版）**：`getInscribedRadius()` 只是返回成员变量，**计算它的代码在没随包安装的 `layered_costmap.cpp` 里**，看不见。

**实测/出处**：`E-15`。稳定：global 0.2249 / local 0.2248，**8 个独立距离桶都成立**（0.2238~0.2254）。
**面试话术**：「我据此把「过门净宽」按 `2 × 0.2249 = **0.4498 m**` 算，而不是拍脑袋的 0.44 m。」

### Q：哪些层「配了但不生效」？ 🔥

**一句话**：`local_costmap` 里那段 `static_layer` **配了但不生效**。

**为什么**：`local_costmap` 的 `plugins` 列表是 `[voxel_layer, inflation_layer]` —— 没写进去的插件**不会被实例化**，下面那段配置就是死文本。

**实测/出处**：`E-14`、`B-6`。证据：local 的致命格 **34** vs global 的 **3475**。

## 3. 全局规划（navfn）

### Q：规划器为什么绕远路？是 bug 吗？ 🔥

**一句话**：**不是 bug**，它**最小化的是「代价积分」而不是「距离」**。

**为什么**：navfn 的代价模型（`navfn.hpp`）：

```
COST_NEUTRAL = 50     基准
COST_FACTOR  = 0.8    代价系数
COST_OBS_ROS = 253    ≥253 视为障碍

导航代价 = 50 + 0.8 × costmap_cost
```

所以「多走 0.9 m 但全程 cost=0」的路径，比「少走 0.9 m 但要蹭着膨胀区走」**便宜得多**。

**实测/出处**：`E-16`。取 `(2.17,1.88) → (-4.50,1.50)`：

| | 路径长度 | 代价积分 | 沿途最高导航代价 |
| --- | --- | --- | --- |
| 只按距离找路（对照组） | **17.60 m** | 3383.0 | 253.0 |
| navfn 实际输出 | 18.50 m | **924.9** | **50.0** |

沿途最高 50.0 = `COST_NEUTRAL` ⇒ **它全程只走 cost=0 的格子**。直路 6.68 m 之所以不可行，是因为离墙只有 0.05 m。

### Q：那换 `use_astar: true` 能让它走直路吗？ 🔥🔥

**一句话**：**不能。实测几乎没差别。**

**为什么**：A\* 的启发式（到目标距离）是**可采纳的**（不高估），所以 A\* 与 Dijkstra **收敛到同一个最优解**。它只是**搜索更快**，不改变「什么是最优」。

**实测/出处**：`E-16`，同一场景 A/B：

| | 点数 | 长度 | 代价积分 |
| --- | --- | --- | --- |
| `use_astar: false`（Dijkstra） | 735 | **18.40 m** | 920.0 |
| `use_astar: true`（A\*） | 739 | 18.50 m | 924.9 |

差 **0.5%**，A\* 甚至**略长**。

> ⚠️ **这是我自己纠过的错**：我原先在 `README.md`、`问题记录.md` E-4、`详解` §6、`map_clearance.py` **四处**都写了「想走直路就换 A\*」。做完 A/B 后四处全部改掉了。
> **面试可以主动讲这个** —— 说明你会**用实验检验文档里的既有结论**。

### Q：那真正该调的是哪个参数？

**一句话**：`inflation_radius` 和 `cost_scaling_factor`。

**为什么**：它们是**唯一**能改变「贴边走的代价有多贵」的旋钮 —— 调小 → 路径更贴墙（更短但更险）。

**实测/出处**：`E-16`、`E-15`。

### Q：目标根本到不了，规划器会告诉我吗？ 🔥🔥

**一句话**：**不会。它会悄悄把目标挪到最近的合法格，然后照常回 `error_code=0`。**

**为什么**：判「目标格有效」用的是**内切半径**。请求点一旦落在 `253` 格里，
navfn 就把它搬到最近的合法格，再正常规划 —— 全程不报错。

**实测/出处**：`E-21`（起点 (0,0)）：

| 请求的目标 | 最宽路线最窄处半径 | navfn 返回路径的**末端** |
| --- | --- | --- |
| (2.17, −3.50) | 0.250 m（勉强可达） | **(2.17, −3.50)** 精确 |
| (−4.50, 1.50) | 0.652 m（宽松） | **(−4.50, 1.50)** 精确 |
| **(−4.50, −3.00)** | **0.100 m（过不去）** | **(−4.65, −3.10)** ← 挪了 **0.18 m** |

**所以**：
- **`error_code=0` + 非空 path ≠ 目标可达。** 要**比一下 `path.poses[-1]`
  与请求目标**，差值就是被挪的距离。
- 想提前知道，用 `tools/map_reachability.py`（1 秒）：
  **最窄处半径 < 0.2249 m 就直接判「几何不可达」**。
- 换个说法：**「导航成功了没有」本身就不是个可信指标** —— 这就是 L4 那句
  「别只看导航成功了没有」的硬证据。

## 4. 局部控制（DWB）

### Q：DWB 是怎么选速度的？ 🔥

**一句话**：**采样式** —— 撒一张速度网格 → 按运动学前推 `sim_time` 秒 → 每条轨迹逐 critic 打分 → 加权求和 → **取总分最小**的那条。

**为什么**：和「优化式」（如 TEB，直接解优化问题）相对。采样式好处是无梯度、不怕非凸；代价是**分辨率受采样数限制**。

**实测/出处**：`E-17`。

### Q：每周期到底评估多少条候选轨迹？ 🔥

**一句话**：

```
候选数 = vx_samples × (vtheta_samples + 1) − 1
```

注意 **`+1`** 和 **`−1`**，且 `vy_samples` **完全不参与**。

**为什么**：θ 网格多一个「原点」（不转）；最后减去「全零速度」那条（静止不算候选）；差速轮 `vy` 恒为 0，所以不参与。

**实测/出处**：`E-17`。

| `vx_samples` / `vtheta_samples` | 实测候选数 | 公式 |
| --- | --- | --- |
| 20 / 20 | **419** | 20×21−1 |
| 10 / 20 | **209** | 10×21−1 |

### Q：critic 的 `scale` 为什么和配置文件里写的不一样？ 🔥🔥

**一句话**：**`MapGridCritic` 家族**（`PathAlign` / `GoalAlign` / `PathDist` / `GoalDist`）的**生效 scale = 配置值 × resolution / 2**。res=0.05 时相当于**除以 40**。

```yaml
# res = 0.05
PathAlign.scale: 32.0   →  生效 0.8
```

**为什么（诚实版）**：那个 **`/2` 的来历未定位**。

**怎么排除别的解释**（这是重点）：我做了 5 组实验，只有分辨率能解释它 ——

| 实验 | 假设 | 结果 |
| --- | --- | --- |
| ① 比例性 | 生效值 ∝ 配置值 | ✅ 成立 |
| ② 改 `angular_granularity` | 是不是角度量化？ | ❌ 无关 |
| ③ 改 `vx_samples` | 是不是采样数？ | ❌ 无关 |
| ④ 改 `linear_granularity` | 是不是线性量化？ | ❌ 无关 |
| ⑤ **改 `resolution`** | 是不是分辨率？ | ✅ **成立**（res=0.025 → ÷80） |

**其他 critic 不受影响**：`RotateToGoal` / `Oscillation` / `BaseObstacle` 的生效 scale **就是配置值**。

**实测/出处**：`E-17`、`详解` §3.4。

### Q：「这一周期为什么选了那个速度」怎么直接看到？ 🔥

**一句话**：DWB 把**每条候选的完整评分**都发出来了 —— 话题 `/evaluation`（`dwb_msgs/msg/LocalPlanEvaluation`，`publish_evaluation` 默认 `true`）。

**为什么**：这是**现成的可观测性**，不用改代码就能做归因。

**实测/出处**：`E-17`。我写了 `tools/probe_dwb.py` 把它摊开。**两条断言每次都成立**：

```
best_index == argmin(total)              ← 选的是总分最小
total == Σ (raw_score × scale)           ← 总分 = 各 critic 加权和
```

这两条成立 ⇒ **我理解了它的评分模型**（不是「看起来对」）。

## 5. 速度链与安全 🔥

### Q：一条速度指令从规划到轮子经过几道关？

**一句话**：**六道**。

```
controller_server  →  /cmd_vel_nav
  → velocity_smoother      →  /cmd_vel_smoothed
  → collision_monitor      →  /cmd_vel
  → mybot_diff_drive_controller  →  轮子
```

**实测/出处**：`E-19`、`B-5`。`ros2 topic info -v` 可逐个确认发布者/订阅者。

### Q：三处都能限速（DWB / smoother / 控制器），到底哪个生效？ 🔥🔥

**一句话**：**`velocity_smoother` 是硬限速者**，下游全被它钳住。

**为什么**：DWB 在**候选采样**阶段限速（它给出的最优轨迹上限 = `max_vel_x`），但 smoother 之后**再钳一道**，且它是**最后一道**，所以实际到轮子的速度 = **min(各级)**。

**实测/出处**：`E-19`。只把 `velocity_smoother.max_velocity[0]` 从 **0.26 改成 0.15**（DWB 的 `max_vel_x` **保持 0.26**）：

| 话题 | 发布者 | vx 范围 |
| --- | --- | --- |
| `/cmd_vel_nav` | `controller_server`(DWB) | **[0, 0.260]** |
| `/cmd_vel_smoothed` | `velocity_smoother` | **[0, 0.150]** |
| `/cmd_vel` | `collision_monitor` | **[0, 0.150]** |

⇒ DWB 发 0.260，**被 smoother 压到 0.150，下游全是 0.150**。

### Q：`collision_monitor` 真的会拦住机器人吗？ 🔥🔥

**一句话**：**会。** 它会**按比例减速**（不是一刀切急停），最后**停在离墙 0.23 m**。

**为什么**：`FootprintApproach` + `action_type: approach` —— 它算「以当前速度再过 `time_before_collision` 秒就会撞」→ **按剩余时间的比例**缩放速度。

**实测/出处**：`E-19`。⚠️ **走正常导航测不出来**（全局规划器**永远不会朝墙冲**），所以我把 `cmd_vel_in_topic` 改成私有话题、**绕开规划器直接喂 0.25 m/s**：

| 前方距离 | 放行 v | 比例 |
| ---: | ---: | ---: |
| 0.49 m | 0.229 | **0.92** ← 开始减速 |
| 0.42 m | 0.146 | 0.58 |
| 0.32 m | 0.083 | 0.33 |
| 0.27 m | 0.021 | 0.08 |
| **0.23 m** | **0.000** | **0.00** ← 停住 |

底盘半径 0.12 m，停在 0.23 m ⇒ **还剩 ~0.11 m 余量**。

**可拟合为**：`放行 v ≈ (d − 0.22) / 1.2`（d=0.32 时拟合 0.083，**实测 0.083**）。**但个别点差约 30%**（d=0.29 拟合 0.058 vs 实测 0.042）⇒ **只能算拟合**，确切实现在未安装的 `polygon.cpp` 里。

### Q：`/cmd_vel` 为什么是 `TwistStamped` 而不是 `Twist`？ 🔥

**一句话**：Jazzy 起控制器**只接受带时间戳的 `TwistStamped`**。发 `Twist` 的现象是「**车收到指令却不动**」—— 不报错。

**实测/出处**：`B-5`。这是个**静默失败**，很难查。

## 7. 我的调试方法论（**最能加分的一节**）

### Q：你怎么确定「你测到的东西是对的」？

**一句话**：**先预测，再测量，最后对比。** 预测不上就说明我理解错了。

**具体例子**（每条都是真做过的）：

| 场景 | 我的预测 | 结果 |
| --- | --- | --- |
| 膨胀公式（`E-15`） | 按公式算每格代价 | **逐格吻合** ⇒ 公式对 |
| DWB 候选数（`E-17`） | `vx×(vθ+1)−1` | 419 / 209 **完全命中** |
| DWB 总分（`E-17`） | `Σ(raw×scale)` | 每条轨迹都成立 |
| 内切半径（`E-15`） | 应等于配置 0.22 | **实测 0.2249**，差 4.9 mm ⇒ **反过来说明有我没看到的计算** |
| `use_astar`（`E-16`） | A\* 应该更直 | **反而略长 0.5%** ⇒ **推翻我文档里的旧说法** |

**话术**：「我给自己定的规矩是 —— **量出来的数字和预期不符时，改结论，不改标准**。」

### Q：改了参数，你怎么知道它**真的生效**了？ 🔥🔥

**一句话**：**用实测数据去反推参数** —— 比 `ros2 param get` 更硬
（那个容易写错参数路径，而且「设上了」不等于「插件在 configure 时读到了」）。

**为什么**：代价地图是参数的**函数**。把同一份实测去对多个「假设值」，看哪个吻合。

**实测/出处**：`F-22`。用 `tools/probe_map_vs_costmap.py` 拿 3300 个采样点，
对 7 个 `inflation_radius` 假设：

| 假设 | 0.4 | **0.55** | 0.7 | 0.8 | 1.0 | 1.2 | 1.5 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 不一致率 | 9.2% | **0.1%** | 7.3% | 14.3% | 25.5% | 33.1% | 46.8% |

**最小值锐利地落在真实值上。** 后来改到 1.2 又用它确认（1.2 → 2.1%），
改回 0.55 再次确认（0.55 → 0.5%）—— **同一招可以双向用**。

### Q：你做过哪些「改动实验」？预测错过吗？ 🔥🔥

**一句话**：做过三个（`E-20`），**7 个预测里 4 个是错的** —— 错的那些我全都记下来了。

| 改动 | 我的预测 | 实际 |
| --- | --- | --- |
| 雷达 10→15 Hz | CPU **+50%** | ❌ 只 **+2.6 个百分点**（GPU 也只 +2.7pp）|
| 膨胀半径 0.55→1.2 | 沿途最高代价**下降** | ❌ **升高**（50.0 → 106.0）|
| 膨胀半径 0.55→1.2 | 路径变长 | ✅ +6%~10% |
| `wall_clearance` = 0.0 | 与改动前逐位一致 | ✅ 3.162 m，日志 0 条 |
| `wall_clearance` = 0.30 | 净空收敛到 0.30 | ✅ 中间 60% 落在 0.292~0.361 |
| `wall_clearance` = 0.10 | 被安全兜底退回 | ✅ 移动 0 / **退回 29** |

**两个错的地方各说明一件事**：
1. **「雷达开销 ≈ 主要开销」是我想当然** —— 实际上那 105% 的 CPU 里雷达只占一小块；
2. **「膨胀半径调大 = 更保守」不等于「更贵」** —— 恰恰相反：「干净走廊」的格子变少了，
   **规划器被迫接受更贵的格子。它仍在最小化代价，但可供选择的路变差了。**

**话术**：「我给自己定的规矩是：**先说预期，再测，再对比**。
改完只能说『好像更好了』，那还不算会改。」

### Q：排查时，什么样的结论是**不能下**的？ 🔥🔥

**一句话**：**排除法只能得出「不是这些」，不能推出「就是那个」。**

**为什么**：把「剩下的那个因素」叫成「原因」，中间缺一步证据。而且「观测」不等于「解释」。

**实测/出处**：`F-9`（把复现不出的故障归因成上游缺陷，还写进了三处文档）、
`E-24`（L5 验收）：

- E-1 把「CPU 争抢」写成「**唯一站得住的相关因素**」—— **用词其实是准的**（「相关」），
  但很容易被读成「已定位」。
- 我去验了它：**成功那一跑循环也在掉速**（9.8 / 7.1 Hz vs 20 Hz 目标），
  `Failed to make progress` 也出现了 **3 次** —— 只是被行为树的恢复机制救回来了。
- 加 16/20 核负载后确实失败，**但是另一种故障**（`recoveries: 0`、`bt_navigator` 报
  「等 action server 确认超时」），**不是** E-1 那个「恢复次数耗尽」。
- ⇒ **「CPU 不够」是背景条件，不是已定位的充分原因。**

**两条硬规则**：
1. 严格区分「**观察到什么**」和「**为什么**」；后者没证据就写**未定位**；
2. 下结论前先问：**换个时间点还能复现吗？** 复现不了的故障不要写成结论。

### Q：写验收 / 复现脚本要注意什么？ 🔥

**一句话**：**「脚本跑完了」和「验证通过了」是两件事** —— 脚本必须**自己带断言**。

**为什么**：验证脚本是最容易被信任的一类证据，所以它的**静默失败最危险**。

**实测/出处**：`F-26`。`tools/run-stuck-repro.sh` 连着两次静默成功：
- 用**相对路径**调 `tools/` 下的脚本 → 从宿主机 `shell.sh` 进来时 cwd 是 `/workspace`，
  两条 python 调用都失败，**脚本却跑完并宣布完成**；
- Nav2 没起来（E-18）→ 三块话题全 0 条消息，脚本照样打印「写入 275 个采样点」。

**修法**：加了两道守卫 —— 前置查 lifecycle，事后查 `/cmd_vel` 有没有非零采样。
**宁可报错，也不要让人拿着空数据去下结论。**

### Q：坐标和格号怎么换算？（**高频陷阱**） 🔥🔥

**一句话**：**PGM 和 `OccupancyGrid` 的行方向是相反的**：

```
PGM      (map_server 存的文件):  r = h − 1 − round((y − oy) / res)      ← 翻
OccupancyGrid / Costmap (话题):  r =     round((y − oy) / res)          ← 不翻
```

**为什么**：PGM 是图像格式，**第 0 行在图像顶部 = 世界 y 最大**；`OccupancyGrid` 的 `data[0]` 在**左下角**。

**实测/出处**：**我在这上面栽了两次**（`F-1` 和 `F-17`）—— 第二次是隔了几十个条目之后、在 `probe_planner.py` 里**又踩了一遍**。
**症状**：数字**自相矛盾**（算出的路径穿墙、长度只有 0.64 m）。

### Q：为什么「数错了」很难发现？ 🔥

**一句话**：**「数错了」和「数对了但结论不对」的现象一模一样。**

**实测/出处**：`F-13`（数 gz 消息条数时数错字段 —— **一条消息里有 360 个同名值**）、`F-16`（看了压缩版 costmap 话题）。
**破解手段**：**先验证「我读的通道对不对」**，再验证「算法对不对」—— 前者只要 5 秒（`ros2 topic list` / `ros2 topic info -v`），后者可能要几小时。

### Q：自己写脚本踩过什么坑？ 🔥

**我整理的 8 条**（都在 `F` 段）：

| 坑 | 现象 | 教训 |
| --- | --- | --- |
| `pkill -f` 自匹配（`F-7`/`F-12`） | 把自己杀了 / 返回 0 但没杀掉 | 模式**写进脚本文件** |
| `ros2 topic echo \| grep`（`F-4`） | 无输出（整体缓存） | 别接管道 |
| `set -u` + `source setup.bash`（`F-3`） | 脚本**静默**退出 | 别用 `set -u` |
| 长驻命令接 `head`（`F-6`） | 假报「没在发布」 | 用 `timeout` |
| 测量函数中途 `return`（`F-18`） | 把「0.64 m」当路径长度（其实是到第一个障碍的距离） | 累积量要**无条件累加** |
| 在发布循环里做耗时的事（`F-19`） | 频率掉到 1.8 Hz < `cmd_vel_timeout`，机器人**一顿一顿** | 耗时操作**独立定时器** |
| 把事件驱动话题当周期源（`F-20`） | 静止时一片空白（`/amcl_pose` 要位移 > 0.25 m 才发） | 先看**发布条件** |
| 自己写出去的占位符读不回来（`F-21`） | 汇总时 `float('-')` 崩 | **写/读的格式定义只能有一处** |

### Q：写自动巡航脚本有什么坑？ 🔥

**一句话**：两个，症状都很有辨识度：

1. **卡死检测必须排除「原地旋转」**（`F-14`）—— 旋转时 x,y 本来就不变。不重置基准的话，**刚切到前进那一瞬间就误判卡死**。
   症状：`err` 恰好聚在转向阈值（0.5）附近：`0.44 / 0.50 / 0.49`。
2. **安全网停距必须 ≥ 底盘半径 + 路径膨胀**（`F-15`）—— 底盘半径 0.12 + 膨胀 0.20 = **0.32**，我一开始设 0.30。
   后果：机器人把自己逼进「**规划器认为的非法格**」→ 起点校验失败 → **所有航点都规划不出路径** → 彻底困死。
   症状：连续几十个航点全是「无路径」，真值一动不动，**但 SLAM 误差只有 0.08 m**。

**修法**：停距提到 **0.40** + 加 `snap()` + 放宽扫描扇角到 ±60°。

## 9. 四个「未定位」的问题，怎么答

> **面试里主动说「这个我没定位到」是加分项**，前提是你能说清「我排除了什么」和「我打算怎么继续查」。

### ① 生效内切半径 0.2249 vs 配置 0.22（差 4.9 mm）

**答**：「我排除了『测错』：8 个独立距离桶、global/local 两张图都稳定在 0.2238~0.2254，而且**膨胀公式本身逐格吻合**。所以是公式里有一个我没看到的分量。
  `getInscribedRadius()` 只返回成员变量，**计算它的 `.cpp` 没随包安装**（`nav2_costmap_2d` 只装了头文件和 `.so`）。
  **继续查的话**：装 `nav2_costmap_2d` 源码包，或直接反汇编 / 读 `.so` 符号。
  **工程上我已经按 0.4498 m 而非 0.44 m 算通道净宽** —— 保险。」

### ② DWB `MapGridCritic` 的 `/2`

**答**：「生效 scale = 配置 × resolution / 2。我用 **5 组实验排除**了角度量化、`vx_samples`、线性量化四个解释，**只剩分辨率**。那个 `/2` 我没找到出处 —— 但**结论是可用的**：换分辨率时我知道该按什么折算。」

### ③ `collision_monitor` 的精确公式

**答**：「**减速行为我量准了**（0.49 m→0.23 m 的完整曲线，停在 0.23 m），也证明了它**按时间比例**而非一刀切。
但拟合 `(d − 0.22)/1.2` 个别点差 30%，**说明真实实现里有我没建模的项**（比如它可能按 `TwistStamped` 的时间戳外插、或对多边形做最近点计算）。
**我只敢说「拟合」，不敢说「就是这条公式」**。」

### ④ 雷达的开销在 `gz sim` 那 105% 的 CPU 里占多少

**答**：「我把**边际成本**量出来了：雷达从 10 → 15 Hz（射线数 +50%），
`gz sim` 的 CPU 只 **+2.6 个百分点**、GPU 只 **+2.7 个百分点** ——
所以**雷达不是主要负载**，这一点是硬的。
但『那 105% 里到底什么占大头』我**没做逐线程归因**，未定位。
**继续查的话**：按线程采样（`top -H` 拿到了线程级数据，但没做归因分析），
或者分别关掉物理步进 / 离屏渲染做剥离实验。」

- 「定位用 AMCL 还是别的（比如 LIO-SAM / FAST-LIO）？」
- 「有没有遇到过**机器人卡住导致 SLAM 发散**？你们怎么在线检测（真值冻结 / 协方差突变）？」
- 「速度链上除了 smoother / collision_monitor，还加自定义的安全层吗？」

```

漂移   open_loop:true 按指令积分 → 打滑就永久累积
发散   根因=机器人卡死(真值冻结)→打滑→odom漂→先验坏→匹配失败
       判据: 真值冻结 + odom误差单调涨 + SLAM误差跟着涨
       反证: 加避障后 odom 仍漂 2.49m, 但 SLAM 误差全程 0.04~0.09m
       地图: 看障碍格世界包围盒 18.7×11.0(正常) vs 19.9×17.2(发散)
costmap  0/252/253/254/255; 读 costmap_raw(0~255) 不读 costmap(压缩到0~100)
        膨胀: d=0→254; d·res≤inscribed→253; d·res>inflation_radius→0; 否则 252·exp(-csf(...))
        「能否过门」由 inscribed 硬阻断; 生效 ≈0.225(反推0.2249/扫峰值0.2255, 差0.6mm未定位)
```
