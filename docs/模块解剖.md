# 模块解剖：每个包里面有什么、对外提供什么

> 与另两份文档的分工：
> - [`模块清单.md`](模块清单.md) —— 干什么 / 怎么跑 / **验证到什么程度**
> - [`问题记录.md`](问题记录.md) —— 踩过的坑长什么样
> - [`上手路线.md`](上手路线.md) —— 怎么学会
> - **本文** —— 里面有什么 / 对外提供什么接口 / 和谁交互。**想读代码时从这篇开始。**

---

## 一、先看全局：22 个包的产出其实只有 4 类

| 产出类型 | 包数 | 包 |
| --- | ---: | --- |
| **可执行节点**（会被 `ros2 run` 起来） | **6** | `mybot_description`、`mybot_bringup`、`gz_sensor_bridge`、`mybot_application`、`mybot_application_cpp`、`autopatrol_robot` |
| **插件库**（被 Nav2 加载，自身不是进程） | **2** | `nav2_custom_planner`、`nav2_custom_controller` |
| **纯配置/资源**（一行代码都没有） | **1** | `mybot_navigation2` |
| **接口定义**（只有一个 `.srv`） | **1** | `autopatrol_interfaces` |
| **教学示例**（自成体系，与主线无关） | **12** | `learn_*`（10）+ `my_tf_cpp` + `my_tf_pkg` |

合计 **25 个可执行** + 2 个 rclcpp 组件 + **2 个 Nav2 插件** + 1 个服务定义。

> **这条分类最有用**：想在代码里找东西时，先问「我要找的是节点、插件，还是配置」——
> 比如「导航为什么走直线」去找 `nav2_custom_planner`（插件），
> 而「导航参数怎么调」在 `mybot_navigation2`（纯配置，没有代码）。

## 二、主线三链：模块之间怎么交互

以下每条边的依据都是代码里的 `create_publisher` / `Subscribe` / launcher 里的 include 关系。

### 仿真链（`./scripts/sim.sh`）

```text
ros2 launch mybot_description gazebo_sim_gz.launch.py
 │
 ├─ gz sim ──────────── 载入 world/custom_room_gz.world（内含 4 个系统插件）
 │                      载入 urdf/mybot/mybot_gz.urdf.xacro（含 gz_ros2_control 插件）
 ├─ ros_gz_sim create ── 把 mybot 生成到仿真里
 ├─ robot_state_publisher ── 从 /robot_description 话题读 URDF
 │                            → 发 base_footprint→base_link→各传感器 的 TF
 ├─ controller_manager spawner ×2
 │     ├─ mybot_joint_state_broadcaster → /joint_states（喂给上面那个 RSP）
 │     └─ mybot_diff_drive_controller   → /odom + odom→base_footprint 的 TF
 ├─ parameter_bridge ─── /clock、/scan、/scan/points（gz↔ROS）
 └─ gz_sensor_bridge_node 或 parameter_bridge（由 sensor_bridge 参数二选一）
       └─ /imu、/camera/image、/camera/depth_image、/camera/camera_info、/camera/points
```

### 导航链（`ros2 launch mybot_navigation2 navigation2.launch.py`）

```text
仅把 map 与 params_file 交给 nav2_bringup/bringup_launch.py：
   config/nav2_params.yaml  +  maps/room.yaml
 │
 ├─ map_server → /map
 ├─ amcl       → map→odom 的 TF（tf_broadcast: true）
 └─ planner_server / controller_server / behavior_server / bt_navigator /
    velocity_smoother / collision_monitor（详见 README「Nav2 的速度链」）
```

### 应用链

```text
mybot_application（4 个例子）         autopatrol_robot（巡检）
  ├ get_robot_pose   → 纯 TF 监听       └ patrol_node（继承 BasicNavigator）
  └ 其余 3 个 → BasicNavigator              ├ 订阅 /camera_sensor/image_raw
                    （nav2_simple_commander）│   └ launch 里 remap 到 /camera/image
                    → 调 Nav2 的 action      └ 调 speech_text 服务 → speaker.py
```

**关键**：`mybot_application` 与 `patrol_node` **都不直接发话题**，它们通过
`nav2_simple_commander` 调 Nav2 的 **action**。所以在这几个节点上看不到
`create_publisher`，那是正常的 —— 想追控制流要去看 Nav2 那一侧的 action server。

## 三、逐包解剖

### robot

#### `mybot_description` — 仿真的主体（节点 + 资源）

| 项 | 内容 |
| --- | --- |
| 可执行 | `scripts/mybot_teleop.py`（192 行）→ 只发布 `TwistStamped` 到 `/cmd_vel`<br>⚠️ **它没有被 install**：`CMakeLists.txt` 只装 `launch urdf config world`，也没把它注册成可执行 —— 所以 `ros2 run mybot_description mybot_teleop` 会失败，`teleop.sh` 是直接按 `src/` 路径跑的 |
| launch | `gazebo_sim_gz.launch.py`（**299 行，主启动**）、`display_robot.launch.py`（只起 rviz 看模型）、`gazebo_sim.launch.py`（classic 版，Jazzy 跑不起来） |
| 模型 | `urdf/mybot/mybot_gz.urdf.xacro`（gz 总装）、`mybot.urdf.xacro`（classic 总装）、`sensor/{laser,imu,camera}.urdf.xacro`、`plugins/gz_{control,sensor}_plugin.xacro` |
| 资源 | `world/custom_room_gz.world`、`config/mybot_ros2_controller.yaml`、`config/rviz/dispaly_model.rviz`（文件名拼写如此） |

**对外接口**：`/cmd_vel`（订阅，`TwistStamped`）、`/robot_description`（发布，话题而非参数 —— `gz_ros2_control` 只能走话题）。

#### `mybot_bringup` — 启动编排

| 项 | 内容 |
| --- | --- |
| 可执行 | `src/odom2tf.cpp`（43 行）—— 订阅 `/odom`，发 `odom→base_footprint` TF |
| launch | `bringup_sim.launch.py`（93 行，**仿真版一键**）、`bringup.launch.py`（50 行，**真机版**）、`urdf2tf.launch.py`（32 行） |

**为什么 `odom2tf` 在仿真里**不启动 —— 仿真里那条 TF 已由 `diff_drive_controller` 发，
再发一次会出现两个发布者打架（真机上里程计不发 TF，才需要它）。

#### `gz_sensor_bridge` — 单向翻译器

| 项 | 内容 |
| --- | --- |
| 可执行 | `gz_sensor_bridge_node`（445 行，本项目最大的单个 C++ 文件） |
| **gz 侧** | `gz::transport::Node::Subscribe` ×5：`/imu`、`/camera/image`、`/camera/depth_image`、`/camera/camera_info`、`/camera/points` |
| **ROS 侧** | `create_publisher` ×5，话题名与上面**完全相同** |

**注意**：它**没有任何 ROS 订阅** —— 是纯单向翻译器。所以它不会自激，也不会和
`parameter_bridge` 互相干扰；两者同时开的危害是「同一话题两个发布者」，不是回环。

### navigation

#### `mybot_navigation2` — 纯配置包（零代码）

| 项 | 内容 |
| --- | --- |
| 代码 | **没有**（`install(DIRECTORY launch maps config rviz)`） |
| launch | `navigation2.launch.py`（62 行）—— 只做一件事：把 `map` 与 `params_file` 喂给 `nav2_bringup` |
| 配置 | `config/nav2_params.yaml`（429 行，8 处 Jazzy 适配都在这里） |
| 地图 | `maps/room.pgm` + `room.yaml`（376×222 px @ 0.05 m，origin `-10.4,-6.53`） |
| rviz | `rviz/mybot_nav2.rviz`（裁剪版，去掉了 TB3 专有的两项） |

#### `nav2_custom_planner` / `nav2_custom_controller` — 插件，不是节点

| 项 | planner | controller |
| --- | --- | --- |
| 类 | `nav2_custom_planner::CustomPlanner` | `nav2_custom_controller::CustomController` |
| **基类** | `nav2_core::GlobalPlanner` | `nav2_core::Controller` |
| 库名 | `nav2_custom_planner_plugin` | `nav2_custom_controller_plugin` |
| 描述文件 | `custom_planner_plugin.xml` | `nav2_custom_controller.xml` |
| 源码 | `src/nav2_custom_planner.cpp` 135 行 + hpp 57 行 | `src/custom_controller.cpp` 146 行 + hpp 61 行 |

**常见误解**：它们 `install(TARGETS ${library_name})`，**没有 `add_executable`** ——
所以 `ros2 run nav2_custom_planner xxx` 必然找不到，这不是打包错误。
它们是**被 `planner_server` / `controller_server` 加载的 .so**。

### app

#### `mybot_application` — 4 个示例节点（都靠 `BasicNavigator`）

| 节点 | 行数 | 通信方式 |
| --- | ---: | --- |
| `get_robot_pose` | 40 | **纯 TF 监听**（`tf2_ros` Buffer + `tf_transformations`）；不碰 action |
| `init_robot_pose` | 21 | `BasicNavigator` → 设初始位姿 |
| `nav_to_pose` | 39 | `BasicNavigator` → 发单点目标 |
| `waypoint_follower` | 52 | `BasicNavigator` → 走路点 |

#### `mybot_application_cpp` — C++ 版

| 项 | 内容 |
| --- | --- |
| 可执行 | `nav2pose`（79 行） |
| 通信 | `rclcpp_action::create_client<NavigationAction>` —— 直接用 action，不经过 `nav2_simple_commander` |

#### `autopatrol_interfaces` — 只有接口

`srv/SpeachText.srv`（拼写如此）：

```text
string text    # 合成文字
---
bool result    # 合成结果
```

#### `autopatrol_robot` — 巡检应用

| 节点 | 行数 | 接口 |
| --- | ---: | --- |
| `patrol_node` | 172 | **继承 `BasicNavigator`**；订阅 `/camera_sensor/image_raw`（代码里的名字）；`create_client(SpeachText, 'speech_text')` |
| `speaker` | 44 | `create_service(SpeachText, 'speech_text', ...)`；`import espeakng` 失败时只打日志（优雅降级） |

**一个容易卡住的点**：`patrol_node.py` 里写的是 `/camera_sensor/image_raw`
（Gazebo classic 相机的名字），而我们的桥发布的是 `/camera/image`。
两者靠 `autopatrol.launch.py` 里的 **remap 接上** —— 只看代码会以为订阅错了。

### learning

12 个包，每个都是**独立可单独跑**的演示，与主线零耦合。
按「演示什么机制」分：

| 演示的机制 | 包 | 关键点 |
| --- | --- | --- |
| 同进程零拷贝 | `learn_compose` | **不是 docker compose**；另有 2 个 rclcpp **组件**（`talker_component` / `listener_component`），由 `intra_process_pubsub` 用 `ComposableNodeContainer` 组装 |
| DDS 共享内存 | `learn_dds_cpp` | `shm_pub` 用 `loaned_message_publisher`（只有 publisher，没有 subscriber） |
| 执行器 | `learn_executor_cpp` / `_py` | 定时器 + 打印线程 ID / 线程数 |
| 生命周期节点 | `learn_lifecyclenode_cpp` / `_py` | `unconfigured → inactive → active` 全走一遍 |
| 消息时间同步 | `learn_message_filter_cpp` / `_py` | `message_filters` 做时间同步 |
| QoS 可靠性 | `learn_qos_cpp` / `_py` | `reliability_test` 演示不同 QoS 组合 |
| TF2 广播/监听 | `my_tf_cpp` / `my_tf_pkg` | 各 3 个可执行：static/dynamic broadcaster + listener |

## 四、几个最容易误解的点（都验证过）

| 现象 | 真相 |
| --- | --- |
| `ros2 run nav2_custom_planner ...` 找不到 | **正常** —— 它们是插件库，没有可执行 |
| `mybot_navigation2` 里一行代码都没有 | **正常** —— 它是纯配置包 |
| `mybot_application` 的节点里看不到 `create_publisher` | **正常** —— 它们走 Nav2 的 action |
| `patrol_node.py` 订阅 `/camera_sensor/image_raw`，仿真里却没有这个话题 | 靠 launch **remap** 到 `/camera/image`；代码不改 |
| `learn_compose` 是不是 docker compose？ | **不是** —— 是 ROS 2 同进程零拷贝演示 |
| `gz_sensor_bridge` 会不会和 `parameter_bridge` 互相回环？ | **不会** —— 它没有任何 ROS 订阅，是单向的。同时开的危害是同一话题两个发布者 |
| `nav2_custom_controller.xml` 文件名没有 `plugin` 字样 | 描述文件名是自由的，**判断是不是插件要看内容里有没有 `<library>`** |
| `ros2 run mybot_description mybot_teleop` 找不到 | **正常** —— `scripts/` 没被 install、也没注册成可执行；入口是 `./scripts/teleop.sh`，它直接按 `src/` 路径跑 |
